# 两次失败启动的控制台输出（原始文本，来源 = 启动器控制台，非引擎日志）

采集时间：2026-09-29
采集方式：启动器 `infer-console.ps1 -Action start` 的控制台输出，由调用方捕获。

⚠️ **来源说明**：这两次尝试各自写了一份 `/home/ai/ninfer-serve.log`，但都**被 07:31 那次成功启动覆盖了**。
所以这两段 FATAL **无法从本仓库的任何日志文件里复现**，属于二手证据。原文如下，未改动。

---

## 尝试一：`--max-context 262144 --kv-capacity 262144`（07:13）

```
正在启动 ninfer（带视觉，KV 262144 tokens，int8，MTP K=3，内核=new）...
正在等引擎把 20 GiB 权重读进显存（约 80 秒）...
引擎在 240 秒内没有就绪。日志尾部：2026-09-29 07:13:05.665  INFO  starting engine /
2026-09-29 07:13:12.539  ERROR startup failed | planning runtime | 6.7s /
2026-09-29 07:13:12.541  FATAL server failed during startup | requested Engine runtime
reservation requires 12004767744 bytes, but only 11330617856 bytes are available for
runtime capacity
```

**由它算出的硬顶**（⚠️ 2026-09-29 订正：早先此处写 `45,794 B/token` 与 `≈247,428 token`，属整数分母与凑数混用；`247,428` 在任何分母下都算不出来 —— ÷45,794 = 247,425.8，取整是 247,426）：

```
12,004,767,744 B ÷ 262,144 token = 45,794.5547 B/token
11,330,617,856 B ÷ 45,794.5547 B/token ≈ 247,422.8  ⇒ 约 247,423 token
```

⇒ `--max-context 245000` 只剩约 2,400 token 余量。
**第二个来源方向一致但精度有限**：`logs/startup-raw.txt` 第 10 行「KV 245,056 tokens … runtime 10.5 GiB」；245,056 × 45,794.5547 = 10.4515 GiB，四舍五入正好印成 `10.5 GiB`；反过来 `10.5 GiB`（两位有效数字）只能把每 token 钉在约 45,788–46,226。
